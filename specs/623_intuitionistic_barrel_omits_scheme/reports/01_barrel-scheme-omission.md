# Intuitionistic Tableau Sub-Barrel Omits `Scheme`: Convention Survey and Verdict

**Task**: 623
**Session**: sess_1786397542_991316_623
**Status**: Researched
**Date**: 2026-08-10

## Executive Summary

The omission is an **oversight, not a design decision**, and the fix is a **one-line addition**
to `Cslib/Logics/Propositional/Tableau/Intuitionistic.lean`.

Two premises in the task description are **falsified** by the evidence:

1. **"The root barrel `Cslib.lean` imports `Scheme` directly instead."** — There is no
   "instead". `Cslib.lean` imports **every** module in the tree: it has exactly **702**
   `public import` lines and there are exactly **702** `.lean` files under `Cslib/`. It is
   machine-generated by `lake exe mk_all --module` and CI enforces the exhaustive listing.
   `Cslib.lean:636` is not evidence of intent about the sub-barrel — it carries no information
   at all, because `Cslib.lean:633-638` also lists `Intuitionistic.Completeness`,
   `.DecisionProcedure`, `.Expansion`, `.Rules`, `.Soundness`, all of which the sub-barrel
   *does* declare. The root barrel lists parent and child alike, uniformly, everywhere.

2. **"Consider dropping the direct line from `Cslib.lean` if sub-barrels are the convention."**
   — This would **break CI**. `CONTRIBUTING.md` (Imports section): *"There is also a test that
   [Cslib.lean] imports all files. You can ensure this by running `lake exe mk_all` locally."*
   Removing line 636 makes `Cslib.lean` non-exhaustive and the next `mk_all` run would add it
   straight back. **Do not touch `Cslib.lean`.**

The genuine finding stands: `Intuitionistic.lean` declares 5 of its 6 children and is the only
file in the intuitionistic tableau cluster that does not re-export `Scheme`, even though
`Scheme` is the cluster's parametric core (`IntMinScheme`, `intScheme`, `minScheme`,
`truthLemma`, `openBranch_countermodel`).

**Recommendation**: add one `public import` line to the sub-barrel, positioned between
`Soundness` and `Completeness`. No other file changes. Zero build-cost impact, zero import-graph
change, no cycle risk, no shake exposure.

## Evidence

### The current sub-barrel

`Cslib/Logics/Propositional/Tableau/Intuitionistic.lean` (lines 10-14) declares, in strict
dependency order:

```
Rules -> Expansion -> Soundness -> Completeness -> DecisionProcedure
```

### The actual dependency chain in the directory

Verified from each file's own import lines:

| Module | Its intra-cluster public imports |
|--------|----------------------------------|
| `Rules` | (none — only `Foundations.Logic.Tableau.SignedFormula`) |
| `Expansion` | `Rules` |
| `Soundness` | `Expansion` |
| `Scheme` | `Foundations.Logic.Tableau.Blocking`, `Tableau.Minimal.Soundness`, `Propositional.Subformula` |
| `Completeness` | `Soundness`, **`Scheme`** |
| `DecisionProcedure` | `Completeness` |

And `Tableau/Minimal/Soundness.lean` publicly imports `Tableau.Intuitionistic.Soundness`.

So the true linear chain is:

```
Rules -> Expansion -> Soundness -> (Minimal.Soundness) -> Scheme -> Completeness -> DecisionProcedure
```

`Scheme` sits **strictly between `Soundness` and `Completeness`**. The sub-barrel's existing
five lines already trace this chain exactly, with the `Scheme` link silently skipped.

### Why the change is provably inert for the build

`Intuitionistic.lean` already imports `Completeness`, and `Completeness.lean:11` carries
`public import ...Intuitionistic.Scheme`. Therefore:

- **Import-graph closure is literally unchanged.** Adding the line introduces zero new edges to
  the transitive closure; it only makes an existing transitive edge direct.
- **No cycle risk.** The barrel already transitively depends on `Minimal.Soundness` (via
  `Completeness -> Scheme`), so the new line adds no reachability that was not already present.
- **No build-cost increase.** `Scheme.olean` is already a build prerequisite of the sub-barrel.
  This matters given the task's cost warning: adding the line does **not** pull the expensive
  `Scheme` module into any target that did not already require it. On an already-built tree the
  incremental cost is re-elaborating the ~19-line barrel file itself.

This also means a targeted verification build is cheap and safe:
`lake build Cslib.Logics.Propositional.Tableau.Intuitionistic` requires exactly the same
prerequisite set before and after the edit. (No build was run during this research — the survey
was static, per the task's cost constraint.)

### What the survey establishes

1. **There is no repo-wide "sub-barrels must be exhaustive" rule.** The split is 13/13, and two
   barrels (`Semantics/Algebra.lean`, `Syntax/SubformulaClosure.lean`) declare *none* of their
   children. So exhaustiveness cannot be asserted as a project convention.
2. **`ORGANISATION.md` does not legislate one either.** Its only barrel language is descriptive
   prose about specific files: *"Tableau barrel (re-exports Tableau/ modules)"* (line 57) and
   *"LoopChecking.lean ... is the barrel ... re-exporting all ten modules"* (line 198). Both
   describe an exhaustive barrel; neither states a rule. `CONTRIBUTING.md` says nothing about
   sub-barrels at all — only about `Cslib.lean` and `lake shake`.
3. **The decisive comparison is local, not global.** Among the three tableau siblings:
   - `Classical.lean` declares its full chain (Expansion, Soundness, Completeness,
     DecisionProcedure) — all 4, even though `DecisionProcedure` alone would suffice
     transitively.
   - `Intuitionistic.lean` declares its full chain **minus one link**.
   - `Minimal.lean` is terminus-only (1 of 3).

   `Intuitionistic.lean` is unambiguously written in the `Classical.lean` "declare the whole
   chain" style — it lists all five chain links it knows about, including redundant ones. It is
   not written in `Minimal.lean`'s terminus-only style (that would be a single
   `DecisionProcedure` line). A file following the declare-the-whole-chain style that skips
   exactly one interior link of the chain is an omission, not a third style.

## Why `Scheme` Belongs on the Sub-Barrel's Surface

`Scheme` is not an internal helper. It is the shared parametric core that both the
intuitionistic and minimal developments instantiate, and it is referenced by name from outside
the directory:

- `Tableau/Minimal/Completeness.lean:11` — `public import ...Intuitionistic.Scheme`
- `Tableau/Minimal/DecisionProcedure.lean:53,56` — cites `truthLemma minScheme`,
  `openBranch_countermodel`
- `Propositional/Metalogic/IntDecidability.lean:73,312,324` and
  `Propositional/Metalogic/MinDecidability.lean:76,278,293` — cite `truthLemma` and
  `openBranch_countermodel` by file
- `CslibTests/TableauConformance.lean` and five other test files import it directly

The task description's stated risk is real and concrete: `Completeness.lean` is the *only* thing
keeping `Scheme` on the sub-barrel's surface, and `Completeness.lean` is a live shake target
whose import list is subject to minimization.

## Shake Exposure Assessment

CI runs `lake shake --add-public --keep-implied --keep-prefix`, ratcheted by
`scripts/check-shake-residue.sh` against a 23-path baseline
(`scripts/shake-residue-baseline.txt`).

- `Cslib/Logics/Propositional/Tableau/Intuitionistic.lean` is **not** in the baseline; the only
  `Tableau` entries are three `Modal/Tableau/` files.
- The precedent is strong: `Classical.lean`, `Tableau.lean`, `SequentCalculus.lean`,
  `LM.lean` and the other 12 exhaustive barrels consist **entirely** of re-export-only
  `public import` lines with zero declarations using them, and none is flagged. A barrel whose
  imports are all pure re-exports is not shake-flaggable in this configuration.
- `--keep-implied` is specifically the flag that stops shake from removing an import merely
  because another import already implies it — which is exactly the shape of the new line
  (`Scheme` is implied by `Completeness`).

**Residual uncertainty (stated, not papered over)**: this was assessed statically. `lake shake`
inspects the build graph and requires a completed `lake build`, which the task's cost constraint
rules out for this research pass. The implementation phase should confirm with
`bash scripts/check-shake-residue.sh --list` (or `--update` only if a genuine new entry appears)
once a build is available. Given the 15-barrel precedent this is a confirmation step, not an
expected failure.

## Recommended Change

**One file, one line.** In
`Cslib/Logics/Propositional/Tableau/Intuitionistic.lean`, insert between the existing
`Soundness` (line 12) and `Completeness` (line 13) lines:

```lean
public import Cslib.Logics.Propositional.Tableau.Intuitionistic.Scheme
```

Resulting import block:

```lean
import Cslib.Init
public import Cslib.Logics.Propositional.Tableau.Intuitionistic.Rules
public import Cslib.Logics.Propositional.Tableau.Intuitionistic.Expansion
public import Cslib.Logics.Propositional.Tableau.Intuitionistic.Soundness
public import Cslib.Logics.Propositional.Tableau.Intuitionistic.Scheme
public import Cslib.Logics.Propositional.Tableau.Intuitionistic.Completeness
public import Cslib.Logics.Propositional.Tableau.Intuitionistic.DecisionProcedure
```

Position rationale: this is the dependency position (`Soundness -> Scheme -> Completeness`),
preserving the file's existing bottom-up ordering, and matches how `Classical.lean` orders its
own chain. It is *not* alphabetical — none of the sibling sub-barrels are alphabetical (only the
machine-generated `Cslib.lean` is).

### Explicitly NOT recommended

- **Do not edit `Cslib.lean`.** It is `mk_all`-generated and CI-enforced to be exhaustive.
  Removing line 636 breaks the imports test and would be reverted by the next `mk_all`.
- **Do not add a "deliberately excluded" comment instead.** No evidence supports deliberate
  exclusion, and `Scheme` is a public-API module cited from six other files and the test suite.
- **Do not normalize the other 12 partial barrels.** The survey shows partial barrels are
  widespread and several (`Semantics/Algebra.lean` at 0/29, `Modal/Metalogic.lean` at 5/14) are
  large, load-bearing, and may be partial on purpose. Bundling them in would turn a one-line
  hygiene fix into an unscoped refactor. If desired, that is a separate task.
- **Do not run a full `lake build`.** Per the task constraint. Use
  `lake build Cslib.Logics.Propositional.Tableau.Intuitionistic`, whose prerequisite set is
  unchanged by the edit.
