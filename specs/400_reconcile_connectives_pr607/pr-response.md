Following up on my earlier comment, a few additive points to help this land. I'd endorse the consolidation that eric-wieser, ctchou, and chenson all suggested — a single `Operators.lean` (or ctchou's three-file split) with one conventions docstring reads better than eight files, and I like eric-wieser's tidier `where and := .and` instance form. On naming I'd like one ruling we can apply library-wide: eric-wieser's point that the `Has` prefix is a Lean-3-ism is fair, but bare `And`/`Or`/`Iff` collide with core/Mathlib and CSLib already uses `Has*` throughout `Foundations/Syntax` (`HasContext`, `HasSubstitution`, `HasFresh`), so there's a real case for keeping it — and I'd settle `impl` vs `imp` in the same breath (I lean `imp`, matching the `impI`/`impE` rule prefixes). On falsum and verum, rather than a `HasBot` class I think the cleaner route is to reuse Mathlib's `Bot`/`Top` (`Mathlib/Order/Notation.lean`), which the Propositional `Defs` already does: a type with a primitive `⊥` then registers faithfully via a derived `HasNot` (`not := neg`) plus the `(φ → ⊥) = ¬φ` bridge you already wrote as `not_eq`, with no new class needed. On the `_def` lemmas I agree with chenson that the normal form should be the notation (collapse `φ.and ψ` to `φ ∧ ψ`, like `List.append_eq`), and I'm happy to help get `grind` to see through the notation so the `Satisfies.*_iff_*` proofs don't need the `=_ *_def` rewrites. The `infixr` ladder (`→` 25, `∨` 30, `⊗` 35, `∧` 36, `¬`/`□`/`◇` 40, `↔` 20) looks good and is more usable than the non-associative `infix` used elsewhere — worth recording in `NOTATION.md`, which is currently silent on connectives; one thing to confirm is that `→` at 25 doesn't shadow core `→` awkwardly in mixed object/meta formulas. Finally, polymorphic axiom development across Propositional/Modal/Temporal/Bimodal wants convenience bundles with defaulted `neg`/`top`, but I'd add those in a follow-up PR on top of these atomic classes rather than grow this one — so all I'd ask here is that the classes stay shaped so a bundle can `extend Bot, HasImpl, HasAnd, HasOr`. Happy to take the follow-up bundle PR, the `NOTATION.md` connectives section, and the `grind`-through-notation issue.
