## THREE root causes (all confirmed against live goal state)

1. **Recognizer-stuck on abstract subformula.** `simp [tryAllPropRules,...] at hsf` is a NO-OP when the
   relevant subformula (`a` in `a→⊥`, or `c` in `a→c`) is an abstract variable, because the decision
   tree evaluates `modalAndOf?` (`(A→(B→⊥))→⊥`) then `modalOrOf?` (`(A→⊥)→B`) BEFORE negPos, and those
   pattern-matches are STUCK on a variable. `find?` never reaches negPos, so hsf stays a giant
   unreduced `match … = some (newBs,newExps,newAcc)`. FIX: `cases` the stuck subformula first.

2. **`cases` consumes the variable (toolchain drift).** Under the OLD toolchain,
   `cases c with | bot => A | atom _ | imp _ _ | box _ => B` kept `c` accessible in `B`. The NEW
   toolchain CLEARS it → `Unknown identifier c/a/a2`. FIX: use NAMED binders
   (`| atom cc => … | imp c1 c2 => … | box cc => …`) and replace every `c` in that body with the
   constructor form (`.atom cc` / `.imp c1 c2` / `.box cc`). Same for `a`/`a2`.

3. **Universe mismatch at the witness.** `branchSatisfiable := ∃ (W : Type*) …` is universe-polymorphic,
   so `hsat`'s `W : Type u_2` and the goal's `∃ W : Type u_3` got DIFFERENT theorem universe params →
   `refine ⟨…, W, m, f, hacc, ?_⟩` fails "W : Type u_2 expected Type u_3". This was MASKED in HEAD
   because the obtain failed before reaching the refine.

```lean

| atom name =>
  simp only [tryAllPropRules, applyPropRule, modalAndOf?, modalOrOf?, modalImpOf?, modalNegOf?,
    RuleResult.isApplicable, Option.getD_some, if_true, Option.some.injEq, Prod.mk.injEq] at hsf
  obtain ⟨hnewBs, _, hnewAcc⟩ := hsf
  subst hnewBs hnewAcc
  refine ⟨[⟨.neg, .atom name, lbl⟩] ++ b, List.mem_cons_self, W, m, f, hacc, ?_⟩
  intro sf' hmem'
  simp only [List.mem_append, List.mem_cons, List.mem_nil_iff, or_false] at hmem'
  rcases hmem' with rfl | hmem_old
  · refine ⟨fun h => by simp at h, fun _ => ?_⟩
    simp only [Satisfies] at hpos
    exact fun ha => hpos ha
  · exact hb sf' hmem_old
```
