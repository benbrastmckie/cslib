## Overview

Refactor CSLib's connective hierarchy in `Cslib/Foundations/Logic/Connectives.lean` to use `class abbrev` for diamond-affected bundle classes, enabling automatic instance chaining across logic intersections. Three classes change from `class ... extends` to `class abbrev`: `FutureTemporalConnectives`, `TemporalConnectives`, and `BimodalConnectives`. Two classes remain as `class extends`: `PropositionalConnectives` and `ModalConnectives`. All 8 atomic `Has*` classes are unchanged. `LTLConnectives` extends `FutureTemporalConnectives` (now a `class abbrev`) and keeps `class extends` since it needs no further chaining. Concrete formula-type instances require no syntax changes. The refactor is done when `lake build` passes and `inferInstance : TemporalConnectives F` succeeds in a `[BimodalConnectives F]` context.

## Goals & Non-Goals

- **Goals**:
  - Eliminate the typeclass diamond by structural design, not suppressed warnings or manual bridge instances
  - Enable `inferInstance : TemporalConnectives F` and `inferInstance : FutureTemporalConnectives F` from `[BimodalConnectives F]`
  - Enable `inferInstance : ModalConnectives F` from `[BimodalConnectives F]` (already works, must not regress)
  - Preserve all existing concrete instance syntax (flat field assignment)
  - Preserve `simp` lemma firing, notation, and definitional equality across projection paths
  - Pass the full CSLib CI pipeline: `lake build`, `lake exe checkInitImports`, `lake lint`, `lake exe lint-style`, `lake test`
  - Update the misleading comment on `BimodalConnectives` to reflect the new design rationale
  - Scale cleanly for future logic bundles (epistemic, deontic, etc.) without requiring bridge instances

- **Non-Goals**:
  - Changing `PropositionalConnectives` or `ModalConnectives` (these remain `class extends`)
  - Adding new connective classes or operators
  - Modifying any atomic `Has*` class
  - Changing concrete formula type inductives or their constructors
  - Adding `HasAnd`/`HasOr` to `PropositionalConnectives` (deferred to task 173)
  - Supporting a fallback bridge-instance approach (the user has explicitly ruled this out)

## Risks & Mitigations

- **Risk**: `class abbrev` for `Type*`-valued bundles has only 3 Mathlib precedents (all `Prop`-valued). PR reviewers may question the pattern.
  **Mitigation**: PR description will cite the scaling argument (0 bridge instances for N logics), the escape hatch (`class extends` can extend a `class abbrev`), and the empirical verification from Round 2 research.

- **Risk**: `LTLConnectives extends FutureTemporalConnectives` may behave differently when `FutureTemporalConnectives` becomes a `class abbrev`.
  **Mitigation**: Phase 2 explicitly tests `LTLConnectives` synthesis. The research confirms `class extends` can extend a `class abbrev` without issue.

- **Risk**: Downstream proof-system files (axiom classes, Hilbert systems) may rely on the specific structure projection names generated by `extends`.
  **Mitigation**: `class abbrev` generates the same `to*` projections. Phase 3 runs the full CI pipeline to catch any regressions.
