### 1. CS5 constructive completeness (the one missing metatheory corner)
**File**: `Cslib/Logics/Modal/Metalogic/Constructive/CS5.lean:156` (documented open blocker);
scaffolding in `CS5Canonical.lean`.
**Description**: CS5 (= CK+T+4+B) is the only system+base combination lacking a completeness
theorem. Not a `sorry` — the theorem is simply unstated. Blocked in the prime-theory canonical
representation because CSLib identifies intuitionistic `≤` with theory-inclusion; a faithful
proof needs `≤` as an independent preorder (mechanized obstructions `cs5Incest_forces_symm`,
`cs5TwoSidedR_iff_cs5Tail`).
**Owned by**: tasks 512 (birelational) and 517 (labelled route). **Blocked**: 512↔517 form a
mutual dependency cycle; 517 is user-gated pending a plan v4 (`/revise 517`).
**Impact**: This is the headline gap for "all combinations complete." Largest effort
(~1500–2500 lines, largely separate mathematics).

## Compositional / "Elegant" Infrastructure Gaps (new findings, no existing tasks)

### 4. Missing composite conservativity bridges (minimal/constructive → classical column)
**File**: `Cslib/Logics/Modal/Metalogic/InterSystem/Modularity.lean`.
**Description**: `IntToClassical.lean` provides IK→K/IT→T/IS4→S4/IS5→S5, and Axis-B provides
MK→IK/CK→IK etc., but the one-line composites `mkDerivable_implies_kDerivable`,
`mtDerivable_implies_tDerivable`, `ms5Derivable_implies_s5Derivable`, `ckDerivable_implies_kDerivable`,
… **do not exist** (confirmed by grep). `Modularity.lean` chains only into the intuitionistic
IS5 corner, never into the classical column.
**Impact**: High-value, low-effort. Completes the "every base collapses into classical" story
that makes the modularity capstone elegant. Separate territory from task 515.

### 5. Duplicated minimal canonical model
**File**: `Cslib/Logics/Modal/Metalogic/Minimal/MinExtension.lean:23-37` (self-documented).
**Description**: `MinCanonicalModel.lean` + `MinTruthLemma.lean` + `MinCompleteness.lean` are the
older MK-only bespoke copies; `MinExtension.lean` is the Axioms-generic version MT/MS4/MS5 use.
MK's own completeness (`mk_completeness`) still runs through the old trio. Refactor MK to
instantiate `mkvalidFC_completeness` and delete the bespoke trio.
**Impact**: Medium. Removes ~1500 duplicated lines; consolidates the minimal base onto one
generic scaffold.

### 6. No uniform frame-condition ↔ axiom correspondence library
**File**: per-system `Systems/*/Soundness.lean` and inline `FC` predicates (`ms4FC`, `is4FC`,
`cs4FC'`, …).
**Description**: Each soundness direction reproves the axiom↔frame-property correspondence
case-by-case. There is no shared "axiom X ⇔ frame property P" library.
**Impact**: Medium. A correspondence library would let new systems be assembled by choosing frame
properties rather than reproving soundness. Larger design effort.

### 7. Bespoke per-system axiom inductives (no schema-union combinator)
**File**: `Cslib/Logics/Modal/ProofSystem/Instances/*.lean` (15 files).
**Description**: Each system re-lists overlapping axiom constructors in a hand-written
`inductive <Sys>Axiom`. The `HasAxiom*` consumption interface is already uniform, so a
schema-union combinator (build `<Sys>Axiom` from a chosen set of shared schema predicates) is
feasible. Coordinate on Zulip per CONTRIBUTING before a refactor this broad.
**Impact**: Medium-large. The deepest "elegant compositional" win, but the highest-risk refactor.
