## High Priority Issues

### 1. `GenericMCSBridge.lean` — 4-way near-verbatim duplication (~300–450 lines)
**Files**:
- `Cslib/Logics/Propositional/Metalogic/GenericMCSBridge.lean` (256 lines)
- `Cslib/Logics/Modal/Metalogic/GenericMCSBridge.lean` (267 lines)
- `Cslib/Logics/Temporal/Metalogic/GenericMCSBridge.lean` (370 lines)
- `Cslib/Logics/Bimodal/Metalogic/Core/GenericMCSBridge.lean` (405 lines) — 1,298 lines total

**Description**: All four files share an identical skeleton: `HilbertOf` tag type →
`InferenceSystem`/`ModusPonens`/`HasAxiomImplyK`/`HasAxiomImplyS`/`MinimalHilbert` instances →
`AlgDS` alias → `derivTreeToList` → `unfoldListImpInTree` → `listDerivToTree` →
`{logic}_deriv_iff_algebraic` → `{logic}_setConsistent_iff_algebraic` →
`{logic}_setMaxConsistent_iff_algebraic`. The `unfoldListImpInTree` (~19 lines) and
`listDerivToTree` (~15 lines) helpers plus the iff-theorem trio recur near-byte-for-byte
across all four (Propositional↔Modal differ only by one `necessitation` arm + renaming). The
trio never uses logic-specific content — only `assumption`/`modus_ponens`/`weakening`.
Temporal and Bimodal *additionally* duplicate their own base/`Fc` sections **internally**
(Temporal lines 66–221 vs 239–370).

**Impact**: ~25–30% of the combined bridge surface is copy-paste. Any change to the
MCS/algebraic-consistency bridge must be made in four places, and four times again for the
`Fc` variants. This is exactly the kind of "bridge that could be stated more generally" the
review targets.

**Not already covered**: Tasks 415, 393, and 439 all treat `GenericMCSBridge` as *shared
infrastructure they build on*, never as a dedup target. Task 415's audit cites "the
abstraction GenericMCSBridge already leans on" as a foundation; 393 parameterizes Lindenbaum/
Classical-completeness files *via* the bridge; 439 is Temporal-only `processNext`
mutual-recursion work. Verified by reading each report.

**Recommended fix** (design only):
1. Collapse Temporal's and Bimodal's *intra-file* base/`Fc` duplication first — make the base
   bridge a specialization of the `Fc`-parameterized one (`fc := .Base`). Lowest risk,
   ~130–150 lines each, no cross-logic abstraction.
2. Extract `unfoldListImpInTree`, `listDerivToTree`, and the
   `deriv_iff_algebraic`/`setConsistent_iff_algebraic`/`setMaxConsistent_iff_algebraic` trio
   into `Cslib/Foundations/Logic/Metalogic/GenericMCS.lean`, parameterized over a typeclass
   capturing "tree-shaped derivation with ax/assumption/mp/weakening", extra rules
   (`necessitation`, temporal duality) passed as an optional hypothesis.
3. Estimated elimination: **~300–450 lines** across the four files.

## Medium Priority Issues

### 2. `maxHeartbeats` inflation concentrated in active logic proofs
**Files**: 72 `maxHeartbeats` sites in `Cslib/Logics/{Bimodal,Temporal}/Metalogic/**`.
Distribution: `3200000` ×33 (16× default), `1600000` ×13, `800000` ×12, `1200000` ×3,
`400000` ×5, **`6400000` ×1 (32× default)** at
`Temporal/Metalogic/Chronicle/CounterexampleElimination/MainElimination.lean:38`.

**Description**: Heavy elaboration-budget inflation, up to 32× the 200,000 default, justified
only by inline comments ("requiring extended heartbeats"). By contrast the mature upstream
dirs (`Foundations`, `Computability`, `Languages`, `Crypto`, …) have **zero** `set_option
maxHeartbeats` — the single hit there is a comment, not a setting.

**Impact**: A high heartbeat ceiling usually signals a proof term/tactic that should be
restructured (intermediate `have`s, lemma extraction) rather than given more budget. It is a
fragility + CI-cost smell, and out of step with the rest of the library's proof style.

**Not already covered**: Tasks 412–414 (proof-simplification) target specific
`simp only [listImp_*, bigconj_*]` lists, not heartbeat budgets; no task mentions heartbeats.

**Recommended fix**: Audit the 3.2M/6.4M sites; restructure the worst offenders to bring the
ceiling down (or document why the budget is irreducible). Group by file.

## Low Priority Issues

### 4. Non-uniform `maxHeartbeats` scoping style
**Files**: 15 file-wide unscoped `set_option maxHeartbeats N` (no `in`) vs 54 declaration-scoped
`set_option maxHeartbeats N in`. Unscoped sites include
`Bimodal/Metalogic/Algebraic/{UltrafilterMCS.lean:34, BooleanStructure.lean:33}` and
`Temporal/Metalogic/{Chronicle/TruthLemma.lean:40, Chronicle/RRelation.lean:29,
DenseSoundness.lean:32, Completeness.lean:47, Soundness.lean:32, MCS.lean:38, WitnessSeed.lean:29,
Chronicle/Frame.lean:28, Chronicle/PointInsertion/{Seeds,Burgess,Splitting,Since}.lean, …}`.

**Description**: A file-wide `set_option maxHeartbeats` silently raises the ceiling for *every*
later declaration, masking which proof actually needs it. The `... in`-scoped convention used
by the majority is cleaner and localizes the cost.

**Impact**: Style inconsistency; hides which declaration is expensive.

**Not already covered**: Tasks 389–392/444 target Propositional docstrings/citations and the
task-180 Temporal diff specifically, not heartbeat scoping.

**Recommended fix**: Convert unscoped sites to `set_option … in` on the specific expensive
declaration (naturally folds into finding #2's audit).
