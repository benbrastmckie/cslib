Thomas and Matthew — picking up on two points from earlier in this thread. Thomas [mentioned](https://leanprover.zulipchat.com/#narrow/channel/513188-CSLib/topic/Propositional.20Logic/near/604025028) wanting a semantic way to show that IPL is conservative over MPL, and Matthew [raised](https://leanprover.zulipchat.com/#narrow/channel/513188-CSLib/topic/Propositional.20Logic/near/605712144) the concern that conservative extensions would be hard to prove in a class-based approach. I've formalized this using the `WithBot` construction we were discussing.

The main result is [`ipl_conservative_over_mpl`](https://github.com/benbrastmckie/cslib/blob/main/Cslib/Logics/Propositional/Semantics/Algebra/Conservative.lean#L163): any bot-free formula derivable in IPL is already derivable in MPL. The proof is short — given any `GeneralizedHeytingAlgebra G` and valuation `v`, we adjoin a fresh bottom via `WithBot G` to get a `HeytingAlgebra`, lift `v` into it, and apply IPL algebraic completeness there. An [embedding lemma](https://github.com/benbrastmckie/cslib/blob/main/Cslib/Logics/Propositional/Semantics/Algebra/Conservative.lean#L133) shows that bot-free evaluation commutes with the coercion `G → WithBot G` — bot-free formulas don't see the fresh bottom — and then injectivity of the coercion closes it.

This is a case where the `bot_val` parameter pays off directly. MPL completeness quantifies over all `bot_val` values in a GHA, and the `WithBot` construction gives the bridge to the `bot_val = ⊥` world of IPL. The module also includes the validity subsumption chain `GHAValid → HAValid → BAValid` and a [`HeytingAlgebra` instance for `WithBot G`](https://github.com/benbrastmckie/cslib/blob/main/Cslib/Logics/Propositional/Semantics/Algebra/Conservative.lean#L106) that should be independently useful. The full file is [here](https://github.com/benbrastmckie/cslib/blob/main/Cslib/Logics/Propositional/Semantics/Algebra/Conservative.lean).
